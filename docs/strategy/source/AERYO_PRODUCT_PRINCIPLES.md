# AERYO Product Principles

Version: 1.0

---

# Purpose

This document guides all product decisions.

When uncertainty exists, these principles take precedence.

---

# Principle 1

Opportunity Over Information

Users do not want weather.

Users want opportunities.

Translate information into action.

Preferred:

Excellent conditions today.

Avoid:

Raw forecast data without context.

---

# Principle 2

Intelligence Over Utility

Aeryo should interpret data.

Not merely display it.

The product should answer:

What should I do?

Not:

What does this data mean?

---

# Principle 3

Confidence Over Complexity

Reduce uncertainty.

Increase confidence.

Every feature should help users make better decisions.

Avoid exposing unnecessary complexity.

---

# Principle 4

Discovery Over Monitoring

Most weather apps monitor.

Aeryo discovers.

Focus on:

- New opportunities
- Better locations
- Better timing
- Better conditions

---

# Principle 5

Personalization Creates Value

The same forecast is different for different riders.

Aeryo should understand:

- Weight
- Skill level
- Equipment
- Preferences
- Travel radius

Recommendations should become increasingly personal.

---

# Principle 6

Community Is Signal

Community exists to strengthen intelligence.

Community should answer:

What is happening right now?

Not:

How do we maximize engagement?

---

# Principle 7

Recommendations Must Be Explainable

Every recommendation should have a reason.

Example:

Recommended because:

- 21-25kt
- Low gust risk
- Matches your 9m kite
- High confidence forecast

Users should understand recommendations.

---

# Principle 8

Trust Is More Important Than Growth

Incorrect recommendations destroy trust.

Trust is difficult to regain.

Never sacrifice reliability for engagement.

---

# Principle 9

Focus Beats Features

Do not build features because competitors have them.

Build features because they improve decisions.

Avoid feature accumulation.

Avoid complexity.

---

# Principle 10

The Homepage Is Sacred

The homepage should answer:

What is my best opportunity?

Everything else is secondary.

---

# Principle 11

Build for Frequent Use

The ideal user opens Aeryo daily.

Features should create repeat value.

One-time novelty features are low priority.

---

# Principle 12

Community Follows Utility

Do not build community first.

Build value first.

Community grows around value.

---

# Principle 13

 Explain Before Automating

Recommendations should not feel magical.

Users should understand why the recommendation exists.

Trust grows through transparency.

---

# Principle 14

 Premium Means Less

Premium products remove noise.

Premium products simplify complexity.

Premium products focus attention.

Whenever possible:

Remove instead of adding.

---

# Principle 15

 The Long-Term Vision

Today:

Find my session.

Tomorrow:

Find my adventure.

Eventually:

Become the operating system for wind-driven adventures.

---

# Product Decision Framework

Before building a feature ask:

Does this help users discover better opportunities?

Does this improve confidence?

Does this reduce uncertainty?

Does this fit the Opportunity → Intelligence → Signal hierarchy?

If any answer is no:

Reconsider the feature.

---

# Product North Star

Help riders find their next great session.

Everything else is secondary.
